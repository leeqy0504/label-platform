# 视觉数据集管理平台使用手册

## 1. 平台用途

平台用于统一管理视觉数据集、Label Studio 审核任务、UnitTrain 训练任务和训练输出模型。

一条典型工作流如下：

```text
准备服务器数据
  -> 分析并登记数据集 v1
  -> 在 Label Studio 中审核标注
  -> 结束审核并生成 v2
  -> 选择固定版本提交训练
  -> 查看指标、日志和输出模型
```

平台中的已发布版本是不可修改的。需要调整 `v2` 时，应从 `v2` 创建新的审核任务，完成后生成 `v3`，而不是覆盖原版本。

## 2. 访问平台

平台面向内网，不设置平台登录，直接在浏览器中打开部署服务器的地址（`http://10.10.16.58:8080`）

## 3. 页面导航

## 5. 准备数据集

### 5.1 数据必须位于服务器目录

当前网站不是浏览器上传工具。数据集必须提前放到服务器中，并且位于配置的“允许访问目录”下面。

用户在登记时只能浏览允许目录。如果目标目录没有显示，请在侧边栏**系统管理**处添加或启用来源目录。

### 5.2 纯图片目录

纯图片数据集可以使用以下结构：

```text
dataset/
└── images/
    ├── 00001.jpg
    ├── 00002.jpg
    └── 00003.png
```

纯图片目录没有标注，登记时必须填写“初始类别”。多个类别使用英文逗号分隔，例如：

```text
person, car, bicycle
```

登记后数据集通常处于“待标注”状态，可以创建 Label Studio 审核任务进行标注。

### 5.3 COCO 数据集

推荐结构：

```text
dataset/
├── images/
│   ├── 00001.jpg
│   └── 00002.jpg
└── annotations.json
```

`annotations.json` 必须是完整 COCO 对象，并包含：

```json
{
  "images": [],
  "annotations": [],
  "categories": []
}
```

**重要要求：**

- `images[].file_name` 必须是相对于所选数据集目录的有效路径，例如 `images/00001.jpg`。
- COCO 检测框格式是 `[x, y, width, height]`，不是 `[x1, y1, x2, y2]`。
- 框和分割掩码不能超出真实图片尺寸。
- 同一目录只能存在一个可识别的 COCO 或 Label Studio 标注源。
- 当前不接受同时存在 `annotations/train.json` 和 `annotations/val.json` 的目录。
- 多份 COCO JSON 应先合并为一个文件，再进行登记。

如果需要保留已有切分，可以在 COCO `images[]` 中添加：

```json
{
  "id": 1,
  "file_name": "images/00001.jpg",
  "width": 1920,
  "height": 1080,
  "split": "train",
  "group_key": "sequence-001"
}
```

`split` 可取 `train`、`val` 或 `test`。相同 `group_key` 的图片会保留在同一个切分中。

### 5.4 Label Studio 导出

平台也能识别受支持的 Label Studio JSON/ZIP 导出到用户端主机。

### 5.5 默认数据切分

没有显式 `split` 时，平台当前使用：

- 训练集：80%
- 验证集：20%
- 测试集：0%
- 随机种子：42

相同输入会获得稳定的切分结果。平台不会仅根据 `images/train/` 或 `images/val/` 目录名称推断切分。

## 7. 查看和管理数据集

### 7.1 数据集状态

| 状态 | 含义 |
|------|------|
| 扫描中 | 平台正在分析或登记数据 |
| 待标注 | 数据集没有可用于训练的完整标注 |
| 审核中 | 存在进行中的 Label Studio 审核任务 |
| 可训练 | 当前版本校验通过并且包含标注 |
| 校验失败 | 数据格式、文件或标注没有通过校验 |
| 已归档 | 数据集只读，不能再创建审核或训练任务 |

### 7.2 版本原则

- 已发布版本显示“不可修改”。
- Label Studio 审核不会覆盖输入版本，而是生成下一个版本。
- 在审核界面勾选“删除图片”后，完成审核会从新版本中移除该图片及其标注，旧版本保持不变。

### 7.3 归档数据集

所有内部使用者都可以从数据集列表的操作菜单中归档数据集。

归档后：

- 数据集和历史版本仍然保留。
- 数据集变为只读。
- 不能创建新的审核任务。
- 不能提交新的训练任务。

归档不是删除操作。

## 8. Label Studio 审核

### 8.1 在 Label Studio 中审核

1. 点击“在 Label Studio 中打开”。

2. **新浏览器首次访问 Label Studio 时，输入账号：std@std.com 密码：123123123 登录。**

3. 修改、增加或删除目标框/分割标注。

4. 提交完成的任务。

5. 回到平台刷新审核任务，查看完成数量和进度。

   ![image-20260722154058211](/Users/lee/Library/Application Support/typora-user-images/image-20260722154058211.png)

   

审核时可点击图片工具栏中的“删除图片”按钮标记排除；按钮会切换为“恢复图片”，再次点击即可取消。完成审核后平台生成不包含这些图片的新版本，不能删除到零张图片。

### 8.2 结束审核并生成版本

确认审核结果可以发布后：

1. 在数据集的“Label Studio 审核”页签找到任务。
2. 点击“结束审核并生成版本”。

输出版本是不可变版本。如果仍需修改，应基于该输出版本创建新的审核任务。

### 8.3 删除审核任务

处于“就绪”或“审核中”的任务可以删除。删除审核任务会：

- 删除对应的 Label Studio Project。
- 删除平台中的审核任务记录。
- 保留原始数据集及其所有已发布版本。

它与“删除数据集图片”不是同一个功能。

## 9. UnitTrain 训练

### 9.1 提交训练任务

提交训练需要满足：

- 页面显示“UnitTrain 在线”。
- 数据集状态是“可训练”。
- 至少存在一个不可变版本。

训练页面可选择 Ultralytics 或 RF-DETR。实例分割可使用 YOLO `*-seg` 模型或 RF-DETR `seg-nano`；平台会根据框架自动选择 YOLO polygon 或原始 COCO RLE 输入。

## 11. 系统管理

### 11.1 访问目录

用户登记数据集时只能选择已启用的目录。目录必须是服务器上的有效绝对路径，并且平台服务需要有读取权限。

![image-20260722154141809](/Users/lee/Library/Application Support/typora-user-images/image-20260722154141809.png)

### 11.2 服务连接

“服务连接”显示 Label Studio 和 UnitTrain 的地址、版本、连接状态及 API Key 是否已配置。

点击“测试连接”只验证平台后端能否连接对应服务。

### 11.3 审计日志

审计日志记录数据集、版本、审核、训练、模型和系统操作，可用于追踪资源和时间。

## 12. 后续的优化方向（按照重要性排名）

- 支持分割模型
- 对不同版本的数据集中图片进行去重，SHA-256 公共图片仓库作为长期存储
- 多个数据集的合并，和图片的增删
- sam3对raw数据集预标注
- 数据集版本之间的差异对比
- 使用已有模型对raw数据集做针对性预标注
